Extensions

ECI
The ECI (Extention Creation Interface) is used to create custom user extentions, which adds an extra layer of freedom to Gear Works. Extentions are "Mods" for the Gear Works editor that can add extra uses and improve user experience. You can access the ECI here. Please note that extensions are not officially supported and may not work as expected. Use the following development docs when developing extensions.

gw_ prefix
Every variable and function in the Gear Works backend is prefixed with "gw_" to avoid naming conflicts.

Here is a list of all available "gw_" functions for the editor (you can find full implementation in our source code):

gw_toggleSideBar()

gw_switchToDocs()
Switches Detail Panel to Docs.

gw_switchToConsole()
Switches Detail Panel to Console.

gw_toggleFileBox()
Opens/Closes the file dropdown.

gw_openProject()
Opens a prompt to open a project from the user's computer.

gw_packageProject()
Packages a project (not yet implemented)

gw_stripHTMLTags
Converts html tag strings to corresponding unicode characters (eg: <br> becomes \n).

gw_zoomIn()
Zooms the code editor in.

gw_zoomOut()
Zooms the code editor out.

gw_zoomEqual
Sets the code editor zoom to center.

gw_fullscreen()
Puts the canvas in fullscreen mode.

gw_escapeFullscreen()
Puts the canvas in editor mode.

gw_goInFullscreen(element)
Puts the argument into fullscreen.

gw_goOutFullscreen(element)
Takes the argument out of fullscreen.

gw_isFullscreen()
Returns a bool true if canvas is in fullscreen mode.

gw_log(log)
Logs in the console.

gw_warn(log)
Logs a warning in the console.

gw_error(log)
Logs an error in the console.

gw_clearConsole()
Clears the console.

gw_checkForSecurityIssues(txt)
Returns true if parsed text is determined to contain security issues.

gw_primeScriptForErrors(code)
Returns a new string of code with a try-catch statment wrapped around it.

gw_run()
Runs the project code.

gw_stop()

gw_clearAllSounds()

gw_cabinet{imageNames[], imageUrls[], soundNames[], soundUrls[]}

gw_xtns[]

gw_cabinetRemove(url, type)

Gear Works Files

The .gw1 file
This filetype is used to store Gear Works projects including their code, resources and extensions.

Layout
The .gw1 file has a layout similar to the .gwx file. Please note that the syntax is different between the two files, to be able to noticably tell the difference. It uses "tags" similar to html, but the syntax is slightly different. Each tag must be in the proper order and there must only be one (with the exception of IMAGE, SOUND, and XTEN tags; There can be as many as desired).

  1. The ⇇!DOCTYPE⇔gw1⇉ tag. This tells the interperater that the file is not corrupted and is not outdated.
  2. The ⇇META⇔data⇉ tag. In the "data" section, is a timestamp, or other usefull information. It is ignored in current versions.
  3. The ⇇TITLE⇔new project⇔gw_user⇉ tag. It contains the name of the project, followed by the name of the author.
  4. The ⇇JSCONTENT⇔content⇉ tag. It contains all the code in the project.
  5. The ⇇IMAGE⇔filename⇔content⇉ tag. This contains the name of the image, and a data (base64) url stored in the content.
  6. The ⇇SOUND⇔filename⇔content⇉ tag. This contains the name of the sound, and a data (base64) url stored in the content.
  7. The ⇇XTEN⇔raw⇉ tag. This simply only contains the raw content of a .gwx file.
  8. The ⇇END⇉ tag. This must be found at the bottom of the file. To terminate the interperater.

Special Characters
(Sometimes called *Broken* characters) To prevent errors transpiring through urls, several characters are encoded.

  1. "\n" and "\r" become "↴"
  2. "#" becomes "↯"

The .gwx file
This filetype is used to store Gear Works extensions ("mods"), specifically their code.

Layout
The .gwx file has a layout similar to the .gw1 file. Please note that the syntax is different between the two files, to be able to noticably tell the difference. It uses "tags" similar to html, but the syntax is slightly different. Each tag must be in the proper order and there must only be one (there are no exceptions in this filetype).

  1. The ←!DOCTYPE↭gwx→ tag. This tells the interperater that the file is not corrupted and is not outdated.
  2. The ←META↭data→ tag. In the "data" section, is a timestamp, or other usefull information. It is ignored in current versions.
  3. The ←TITLE↭Name↭Author→ tag. It contains the name of the extension, followed by the name of the author.
  4. The ←OVERVEIW↭Text Content↭Hex Color→ tag. It contains a simple overview (written in html) of the extension followed by a color to assosiate it with. (Note the # in the color will be replaced with a ↯ char)
  5. The ←JSCONTENT↭content→ tag. It contains all the code in the extension.
  6. The ←DOCUMENTATION↭Text Content→ tag. It contains detailed documentation (written in html) of the extension.
  7. The ←END→ tag. This must be found at the bottom of the file. To terminate the interperater.

Special Characters
(Sometimes called *Broken* characters) To prevent errors transpiring through urls, several characters are encoded.

  1. "\n" and "\r" become "↴" (except when written in html, use the <br> tag)
  2. "#" becomes "↯"
